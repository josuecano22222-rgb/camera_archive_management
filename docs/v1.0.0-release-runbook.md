# Camera Archive Management V1.0.0 — operator runbook

This runbook describes the V1.0.0 update for the active branch `arena/e4b9cfae-camera-archive-management`. Keep a controlled maintenance window for schema changes. Demo records are always opt-in; neither install nor migrate creates them.

## This update — archive retirement & credential merge

This branch completely removes the `Archive Asset`, `Archive Ingest Batch`, and `Archive Settings` DocTypes and the `Archive Integrity` report, and merges `Camera Credential` into `Camera` as permlevel-1 (System Manager only) fields. Two new post-model-sync patches run during `bench migrate`:

- `merge_camera_credentials` — decrypts each legacy credential, re-encrypts it under `Camera` through the normal save lifecycle, promotes any pre-isolation plaintext, then retires the standalone DocType and drops its table. It fails closed on duplicate-per-camera records or undecryptable secrets.
- `remove_archive_doctypes` — copies the Motion Event defaults into `CAM Geo Settings` (new **Motion Events** tab), deletes every dependent number card / chart / report / onboarding step / workspace widget, then deletes the DocTypes and **drops their physical tables and `tabSingles` rows**. It fails closed if an external DocType still links a retired one.

> **Destructive change.** Archive-media records (assets, ingest batches) are permanently deleted; camera credentials are preserved on `Camera`. Unlike the initial build, **take a backup before migrating** any site that holds real archive or credential data, and rehearse on a staging clone first. If a patch reports an orphan, ambiguous settings row, duplicate credential, or unresolved reference, stop and inspect the error — do not force-delete rows.

## Safeguards and scope

- Synthetic demo records are never created by install, migrate, or core seeding. They require an explicit site-config Boolean and an explicit command by an authorized operator.
- Demo records are fictional, tagged `CAM-MAP-V1-DEMO`, and excluded from map results unless the user enables the synthetic-data toggle.
- An operator may explicitly enable the demo scenario on `frappe.com`; it must not be mistaken for real operational camera or incident data. Run the cleanup command when finished if samples are no longer wanted.
- Do not modify `siraj_research` or delete/move `sites/frappe.com/private/siraj_tile_cache/`. Tile fetching and shared-cache writes remain disabled until explicitly reviewed and enabled in Siraj/CAM settings.
- Do not run Redis flushes or broad cache-deletion commands as a migration fix.

## Update, build, migrate, restart

Run from the Bench root. Fetch and fast-forward only the active release branch, then verify the release commit printed by the final command:

```bash
cd ~/frappe-bench
git -C apps/camera_archive_management fetch origin arena/e4b9cfae-camera-archive-management
git -C apps/camera_archive_management checkout arena/e4b9cfae-camera-archive-management
git -C apps/camera_archive_management pull --ff-only origin arena/e4b9cfae-camera-archive-management
git -C apps/camera_archive_management rev-parse HEAD
```

Back up the site (required for this destructive update), build the app assets, then run the schema migrations:

```bash
cd ~/frappe-bench
bench --site frappe.com backup --with-files
bench build --app camera_archive_management
bench --site frappe.com set-maintenance-mode on
bench --site frappe.com migrate
```

The V1.0 gallery patch checks DocField ownership via `parent` and Custom Field ownership via `dt`. It preserves gallery metadata and File attachments before retiring the legacy child DocType. If migration reports a genuine orphan, unsafe file, ambiguous File match, or unresolved reference, stop and inspect the error; do not force-delete the legacy DocType or File rows.

Only after migration succeeds, clear the cache, restart, and check the Bench:

```bash
cd ~/frappe-bench
bench --site frappe.com clear-cache
bench --site frappe.com clear-website-cache
bench restart
bench doctor
bench --site frappe.com set-maintenance-mode off
```

If migration fails, keep the site in maintenance mode, capture the full traceback, and fix that specific condition before retrying. Do not run production tests while migration is incomplete. Both new patches are repeatable, so a corrected re-run of `bench --site frappe.com migrate` finishes the remaining cleanup safely.

After migrating, confirm in Desk that the four retired DocTypes and the `Archive Integrity` report no longer appear, the workspace shows 5 number cards and 5 charts, `Camera` has an **Access Credentials** tab visible only to System Manager (with the encrypted Password fields and a **Record rotation** action), and `CAM Geo Settings` has a **Motion Events** tab holding the preserved defaults. Verify a non-manager role cannot see or read the credential fields.

## Troubleshooting the update

**`checkout`/`pull` aborts with "Your local changes … would be overwritten".** Frappe running in developer mode re-exports the workspace JSON to disk during `migrate`, which leaves a local git modification that blocks switching branches. The update never lands until this is cleared. Stash the local change (recoverable), then check out and pull, and confirm the release commit:

```bash
cd ~/frappe-bench
git -C apps/camera_archive_management status --short
git -C apps/camera_archive_management stash push -u -m "pre-update local changes"
git -C apps/camera_archive_management checkout arena/e4b9cfae-camera-archive-management
git -C apps/camera_archive_management pull --ff-only origin arena/e4b9cfae-camera-archive-management
git -C apps/camera_archive_management rev-parse HEAD   # must match the release commit
```

If `rev-parse HEAD` still prints an older commit, the checkout did not happen — resolve the remaining local changes before building or migrating. Only after the correct commit is checked out should you re-run `bench build`, `bench migrate`, the cache clears, and `bench restart`. A workspace JSON that reappears as modified after a later `migrate` is the same developer-mode re-export; it is harmless as long as the parsed chart/card counts still match.

**`… must stay removed` after the branch switch.** Git removes the tracked source files of a deleted DocType but leaves untracked `__pycache__` artifacts behind, so the folder still exists and the no-trace check fails. Remove the retired folders explicitly (this also prevents a stale exported JSON from being re-imported on a later migrate):

```bash
cd ~/frappe-bench/apps/camera_archive_management
git clean -fdx -- \
  camera_archive_management/camera_archive_management/doctype/archive_asset \
  camera_archive_management/camera_archive_management/doctype/archive_ingest_batch \
  camera_archive_management/camera_archive_management/doctype/archive_settings \
  camera_archive_management/camera_archive_management/doctype/camera_credential \
  camera_archive_management/camera_archive_management/report/archive_integrity \
  camera_archive_management/camera_archive_management/number_card/archive_assets \
  camera_archive_management/camera_archive_management/number_card/pending_archive_index \
  camera_archive_management/camera_archive_management/number_card/failed_ingest_batches \
  camera_archive_management/camera_archive_management/onboarding_step/check_archive_integrity_and_indexing \
  camera_archive_management/camera_archive_management/onboarding_step/create_an_archive_asset_record \
  camera_archive_management/camera_archive_management/onboarding_step/prepare_an_idempotent_ingest_batch \
  camera_archive_management/camera_archive_management/onboarding_step/review_archive_policy_and_defaults
```

This is a one-time disk cleanup; no re-migrate is needed because the DocTypes are already gone from the database.

**`Command 'python' not found`.** Use `python3`, or the Bench environment interpreter so optional geo dependencies resolve:

```bash
cd ~/frappe-bench/apps/camera_archive_management
~/frappe-bench/env/bin/python -m unittest camera_archive_management.geo.test_tile_cache camera_archive_management.geo.test_geometry camera_archive_management.camera_archive_management.test_doctype_interface -v
```

The authoritative check is the full site suite: `bench --site frappe.com run-tests --app camera_archive_management`.

## Explicit sample-data command

To add the fictional sample scenario on a site (including `frappe.com` when deliberately requested), set the Boolean flag and invoke the generator explicitly:

```bash
cd ~/frappe-bench
bench --site frappe.com set-config camera_archive_allow_demo_data True --parse
bench --site frappe.com execute camera_archive_management.setup.demo_data.create_demo_scenario
```

A successful create returns counts for 12 cameras, four camera areas, eight vehicles, four demo-only vehicle types, and 72 events. Each camera gets two distinct attached illustrations and exact seven-decimal coordinate strings; four vehicles have their own illustrations and the others use their vehicle-type illustration fallback. The 72 Entry/Exit events form nine timestamped route points per vehicle and carry synthetic nearby-camera context. The generator is idempotent when the full tagged scenario already exists; if it reports a partial scenario, inspect the tagged records and use the delete command before regenerating.

After visual verification, remove only the scenario-tagged sample records if desired, then disable the opt-in:

```bash
bench --site frappe.com execute camera_archive_management.setup.demo_data.delete_demo_scenario
bench --site frappe.com set-config camera_archive_allow_demo_data False --parse
```

With the flag disabled, create/delete commands return a clear refusal and perform no database work.
