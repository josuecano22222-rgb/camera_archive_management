# إدارة أرشيف الكاميرات — دليل التهيئة الموجّهة

يتبع هذا الدليل إطار Frappe الأصلي **Module Onboarding → Onboarding Step** كما هو مطبق في تطبيق Siraj-Research العام. تسمى القائمة داخل التطبيق **Camera Archive Management Setup** وهي مضمنة في مساحة عمل إدارة أرشيف الكاميرات. تقود المستخدم من البيانات الجغرافية والتصنيفات المرجعية إلى كاميرا ومركبة ورصد حركة متحقق منه. توجد سجلات JSON في `camera_archive_management/camera_archive_management/module_onboarding/` و`onboarding_step/`؛ وتتضمن مساحة العمل كتلة التهيئة المسماة وتتحقق الاختبارات من أهداف الخطوات.

## إظهار قائمة التهيئة

يخفي Frappe v15 التهيئة عندما يكون الإعداد العام **Enable Onboarding** معطلاً. على System Manager فتح **System Settings** وتفعيل **Enable Onboarding** ثم الحفظ. يتعمد التطبيق عدم تغيير الإعداد العام عند التثبيت، لأن ذلك قد يُظهر مسارات تهيئة تابعة لتطبيقات أخرى أيضاً. أعد تحميل Desk وافتح `/app/camera-archive-management`.

تظهر القائمة إلى System Manager وCAM Operator وCAM Archive Manager وCAM Geo Administrator. ويمكن لأدوار CAM Viewer وCAM Analyst للقراءة فقط استخدام مساحة العمل والبطاقات والمخططات والتقارير، لكن قائمة التهيئة كثيفة الإنشاء لا تعرض لهما. بعض الخطوات اختيارية لأن الصلاحيات موزعة عمداً بين المجال الجغرافي والتشغيلي. لا تمنح قائمة التهيئة صلاحيات. اطلب من System Manager إسناد الحد الأدنى من أدوار CAM اللازمة قبل البدء:

| الدور | العمل المعتاد |
|---|---|
| CAM Viewer | قراءة مساحة العمل والخريطة والتقارير والسجلات |
| CAM Operator | صيانة سجلات الكاميرات والمركبات والأحداث التشغيلية |
| CAM Analyst | مراجعة التقارير وبيانات الحركة المصرح بها |
| CAM Archive Manager | صيانة سجل الكاميرات وسجلات الحركة |
| CAM Geo Administrator | صيانة مجموعات البيانات والمناطق والحدود الجغرافية |
| System Manager | إعدادات الموقع وبيانات اعتماد الكاميرا المقيدة |

بيانات اعتماد الكاميرا أضيق من صلاحيات التهيئة العامة: فهي موجودة في تبويب **Access Credentials** المقيد داخل نموذج الكاميرا (permlevel 1)، ولا يقرأه أو يكتبه إلا System Manager. خطوة بيانات الاعتماد اختيارية ولا يفتحها إلا مستخدم مخول. إذا تعذر الوصول إلى خطوة، اطلب الدور الصحيح؛ لا توسّع صلاحيات نوع المستند لمجرد جعل رابط التهيئة قابلاً للنقر.

## التسلسل الموصى به

1. **مساحة العمل والوصول:** عيّن المشغل والمحلل ومدير الأرشيف والمسؤول الجغرافي.
2. **الإعداد الجغرافي والمصدر:** قرر هل يلزم العمل محلياً أو دون اتصال؛ وراجع مجموعة البيانات النشطة وسياسة البلاطات والترميز الجغرافي عبر الإنترنت وترخيص المصدر. يتضمن تبويب Motion Events أهمية الحدث الافتراضية ونصف قطر تنبيه الكاميرات القريبة.
3. **البيانات الجغرافية المرجعية:** سجّل مجموعة بيانات وأنشئ المناطق الإدارية، ثم استورد هندسة الحدود وتحقق منها. يتضمن التثبيت حدوداً عامة لدول Natural Earth فقط، وليست حدوداً قانونية أو تغطية محلية تفصيلية.
4. **التصنيفات التشغيلية:** أنشئ مناطق الكاميرات التشغيلية، وراجع أنواع الكاميرات وأنواع المركبات. يضيف التطبيق التصنيفات الأساسية المفقودة للكاميرات والمركبات دون استبدال التغييرات المحلية.
5. **المخزون:** سجّل الكاميرا بإحداثيات دقيقة ومصدر موثق؛ ولا تخزن أسرار الحساب إلا في حقول Access Credentials المحمية عند الحاجة الحقيقية. أضف هويات المركبات عند وجود ما يسندها وعند التصريح بذلك.
6. **الرصد:** سجّل حدث حركة بوقت واتجاه دقيقين، ولا تربطه بمركبة إلا إذا كانت الهوية مدعومة.
7. **دورة الجودة:** افحص الخريطة وتقارير تغطية الكاميرات والخط الزمني لحركة المركبات وجودة المواقع. أصلح المشكلات في السجلات المصدرية وأعد تشغيل التقرير المناسب.

للتفاصيل، راجع [01 — البيانات الجغرافية المرجعية](01-reference-data.md)، و[02 — سجل الكاميرات](02-camera-registry.md)، و[03 — الحركات](03-movements.md)، و[04 — التشغيل والخصوصية](04-operations.md).

## قراءة لوحة المعلومات المباشرة

تتضمن مساحة العمل خمس بطاقات أرقام مباشرة: إجمالي الكاميرات والكاميرات النشطة ومناطق الكاميرات والحركات المسجلة والمركبات المسجلة. وتشمل المخططات حالة الكاميرات والحركات اليومية واتجاه الدخول/الخروج ونوع المركبة والكاميرات حسب المنطقة.

هذه مؤشرات لفرز الأولويات وليست أدلة قائمة بذاتها. قد يعني الصفر عدم وجود سجلات أو قصور الصلاحيات أو عدم اكتمال الاستيراد؛ كما تجمع المخططات السجلات المرئية للمستخدم الحالي. انتقل دائماً إلى القائمة أو التقرير المصدر، وتحقق من التاريخ والمنطقة الزمنية وتغطية المصدر، وراعِ صلاحيات الدور قبل الاستنتاج التشغيلي.

## أوامر تحديث وتحقق آمنة

من مجلد Bench، حدّث فرع التطبيق الذي يتضمن هذه التغييرات، وأعد بناء الأصول، ونفذ الترحيل على موقع `frappe.com` وامسح ذاكرته المؤقتة. لا تنفذ ترحيلاً على موقع إنتاج دون النسخة الاحتياطية المعتادة وإجراء اعتماد التغيير.

```bash
# من مجلد Bench. راجع git status --short أولاً واحفظ أي تغييرات محلية.
APP=apps/camera_archive_management
BRANCH=arena/8970c81a-camera-archive-management
git -C "$APP" status --short
git -C "$APP" fetch origin "$BRANCH"
if git -C "$APP" show-ref --verify --quiet "refs/heads/$BRANCH"; then
  git -C "$APP" switch "$BRANCH"
else
  git -C "$APP" switch --track -c "$BRANCH" "origin/$BRANCH"
fi
git -C "$APP" pull --ff-only origin "$BRANCH"
bench build --app camera_archive_management
bench --site frappe.com migrate
bench --site frappe.com clear-cache
```

إذا لم يكن التطبيق مثبتاً إلا على موقع جديد، ثبّته قبل الترحيل (لا تكرر ذلك على موقع مثبت مسبقاً):

```bash
bench --site frappe.com install-app camera_archive_management
bench build --app camera_archive_management
bench --site frappe.com migrate
```

للتحقق من ملفات JSON ومراجع مساحة العمل الثابتة دون موقع حي، شغّل الاختبارات من جذر المستودع:

```bash
python -m unittest camera_archive_management.camera_archive_management.test_workspace -v
python -m compileall -q camera_archive_management
```

لا يغني الاختبار الساكن عن تجربة قائمة التهيئة في موقع Frappe يعمل، مع أدوار Desk وبيانات الموقع والمتصفح الفعلية. بعد الترحيل، تحقق من **Enable Onboarding** وظهور العناصر حسب الدور وإجراءات الإنشاء والحفظ ونتائج المخططات ومسارات التقارير في الموقع المستهدف.
