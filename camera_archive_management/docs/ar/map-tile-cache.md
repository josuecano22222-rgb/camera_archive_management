# بلاطات خريطة الكاميرات: ذاكرة Siraj المشتركة والاتصال الاحتياطي بالإنترنت

تستخدم خريطة أرشيف الكاميرات فهرس البلاطات المثبت من `siraj_research`؛ ولا تعرّف عناوين المزود ولا تستبدلها. تقرأ وتكتب فقط ضمن شجرة `siraj_tile_cache` الخاصة بالموقع، وبالتنسيق المتوافق مع Siraj:

```text
private/siraj_tile_cache/<layer>/<_|overlay>/<z>/<x>/<y>.<format>
```

يقابل متغير `base` في API مجلد Siraj القياسي `_`؛ ويقبل القراءة من مجلد `base` الصريح الموجود مسبقاً للتوافق. عند وجود البلاطة نفسها في الموضعين، تكون الأولوية للمجلد القياسي `_`.

يتحقق الخادم من صلاحية قراءة Camera قبل تقديم البلاطات. يكون جلب المزود من جهة الخادم وبأولوية الذاكرة المؤقتة، ويظل معطلاً ما لم تتحقق جميع الشروط التالية:

1. تفعيل `CAM Geo Settings.enable_online_tile_fetch`.
2. تفعيل `CAM Geo Settings.allow_tile_cache_write`.
3. تفعيل `Geo Settings.allow_tile_fetch` في Siraj Research.
4. تفعيل الطبقة المطلوبة في إعدادات Geo في Siraj.
5. ألا تكون قيمة إعداد الموقع الاختياري `camera_archive_allow_online_tile_fetch` مساوية لـ false.

إعدادا CAM معطلان افتراضياً. راجع شروط المزود المحدد الحالية وحقوق التخزين والاحتفاظ والإسناد وسياسة التواصل/معرّف User-Agent قبل التفعيل. تعرض الواجهة الإسناد من فهرس طبقات Siraj. لا يضيف التطبيق نقاط نهاية مزود أو مفاتيح API من عنده. إذا تعذر تحميل Siraj أو إعداداته الجغرافية، فتعيد نقطة الإعدادات عدم وجود طبقات نقطية، ويبقى الجلب عبر الإنترنت معطلاً؛ ولا يخمن التطبيق فهرساً أو إسناداً بديلاً.

## قائمة الفحص وتحليل السبب الجذري

قبل السماح بالاتصال بمزود على موقع ما، نفذ الفحوص التالية من جذر Bench وراجع مصدر Siraj المثبت وسياسة المزود. لا تنسخ عناوين URL من هذا التطبيق ولا تخمنها:

```bash
bench version
rg -n --glob '*.py' --glob '*.js' --glob '*.md' \
  'LAYERS|_resolve_url|_ENABLE_FLAG|allow_tile_fetch|User-Agent|attribution|tile_cache' \
  apps/siraj_research/siraj_research
rg -n 'tile_cache_days|allow_tile_fetch|enable_.*standard|enable_.*aerial|enable_.*hybrid' \
  apps/siraj_research/siraj_research/doctype
find sites/frappe.com/private/siraj_tile_cache -type f \
  \( -path '*/standard/*/5/13/8.*' -o -path '*/aerial/*/5/13/8.*' \
     -o -path '*/hybrid/*/5/13/8.*' \) -print 2>/dev/null
```

لكل مزود مفعّل، تحقق من مواصفة الطبقة الحية لدى Siraj وشروطها المرتبطة الحالية: محلل URL أو المضيف، ونوع MIME وصيغة الصورة، والإسناد، و`User-Agent` وترويسات/مفاتيح الطلب المطلوبة، وحقوق التخزين والاحتفاظ، ونطاقات التكبير. طابق أسماء وقيم حقول `Geo Settings` مع `tile_cache._settings()` و`_ENABLE_FLAG`، وتأكد من كتابة Siraj للبلاطات الأساسية في `_` والتراكبات في `overlay`. لا تفعّل الجلب حتى تتوافق كل هذه الفحوص مع إصدار Siraj الجاري. كان السبب الجذري لاستجابات 417 السابقة في التطبيق هو تعبير تحقق نقطة النهاية القديمة `^(?:0|[1-9][0-9]?)$` الذي رفض قيم XYZ الصحيحة التي تبلغ 100 أو أكثر؛ أما المعالج الحالي فيحلل الأعداد العشرية ثم يطبق حدود XYZ المعتمدة على مستوى التكبير. استخدم طلبات التحقق أدناه للتأكد من إصلاح النشر.

## البنية وتدفق البيانات

1. يتحقق `camera_archive_management/api/tiles.py` من صلاحية قراءة Camera، ويفحص الطلب وضوابط CAM/Siraj، ويعيد إعداد طبقات يتضمن الإسناد. يقدم النتائج المخبأة أولاً، ويجدول تحديثاً واحداً للبيانات القديمة عند الحاجة، ويحد من المعدل، ويرسل ترويسات حالة/ذاكرة مؤقتة وتشخيصات محدودة التكرار.
2. يتولى `camera_archive_management/geo/tile_cache.py` قوائم السماح الصارمة لإحداثيات XYZ والطبقات، والقراءة الآمنة من الذاكرة المشتركة، وحل مزود Siraj، والتحقق المحدود من HTTP والصورة، وأقفال تفويت مشتركة بين العمليات، وحد التوازي لكل عامل، والكتابة الذرية. ولا يستخدم إلا فهرس Siraj المثبت والذاكرة المشتركة الخاصة.
3. يوفر نوع المستند `CAM Geo Settings` عناصر تحكم افتراضية الإيقاف لجلب البلاطات والكتابة في الذاكرة، ومهل اتصال محدودة.
4. تحمّل `camera_archive_management/camera_archive_management/page/camera_archive_map/camera_archive_map.js` إعداد الطبقات المصرح بها، وتحافظ على مرشحات الخريطة ومساراتها الموجودة، وتعرض أخطاء الذاكرة/المزود/البلاطات دون حلقة إعادة محاولة.
5. تتضمن `camera_archive_management/geo/test_tile_cache.py` اختبارات معزولة قابلة للتشغيل؛ ويعرض هذا المستند فحوص الموقع. لا تعدل ملفات Frappe أو ERPNext أو Siraj الأساسية.

تدفق الطلب: Desk ← API بلاطات الكاميرا المصادق عليه ← التحقق من الإحداثيات والطبقة ← قراءة ذاكرة Siraj المشتركة ← عند الغياب/القدم والسماح بكل ضوابط السياسة، قفل ثم إعادة تحقق ← طلب محدود عبر محلل Siraj ← التحقق من صورة HTTP والكتابة الذرية إلى بنية الذاكرة القياسية في Siraj ← إرجاع البلاطة أو خطأ JSON محدود. تعاد البلاطات القديمة فوراً بينما قد تعمل مهمة خلفية على تحديثها؛ ولا تعتمد إصابات الذاكرة على اتصال المزود.

## السلوك أثناء التشغيل

- تتحقق الإحداثيات الصحيحة كأعداد عشرية صحيحة، مع تكبير من 0 إلى 19 وشرط `0 <= x,y < 2^z`. تعيد الطلبات غير الصالحة HTTP 400 مع JSON بدلاً من استجابة تحقق Frappe العامة HTTP 417.
- تقدم البلاطات الموجودة قبل أي تحقق من الشبكة. تعيد البلاطة الحديثة الترويسة `X-CAM-Tile-Cache: HIT`؛ أما البلاطة الصالحة منتهية الصلاحية فتعاد فوراً بحالة `STALE` مع جدولة تحديث خلفي واحد غير مكرر.
- قد يكون HTTP 404 في المتصفح من نقطة البلاطات مسار API ناجحاً مع نتيجة تفويت ذاكرة (`tile_missing`)، وليس غياباً لطريقة Frappe. إذا لم توجد بلاطة XYZ مخبأة وكان الجلب عبر الإنترنت معطلاً افتراضياً، تعرض Leaflet خطأ `tileerror` للصورة المفقودة، وتظل علامات الكاميرات والمركبات مستقلة عن توفر الطبقة النقطية. أضف البلاطات مسبقاً إلى الذاكرة الخاصة المشتركة أو فعّل جلب المزود صراحة بعد فحوص السياسة أعلاه.
- عند تفويت الذاكرة، تستخدم طلبات الكاميرا افتراضياً مهلة اتصال ثانيتين ومهلة قراءة ثلاث ثوان. تقيد إعدادات CAM Geo كل مهلة إلى 1–5 ثوان. تتشارك الطلبات المتزامنة للبلاطة نفسها قفلاً استشارياً بين العمليات باستخدام 4096 جزء تجزئة ثابتاً؛ ويحدد Semaphore لكل عامل الجلب المتزامن من المنبع بأربعة. يعاد فحص الذاكرة بعد الحصول على القفل.
- يجب أن تطابق استجابات المزود الناجحة نوع MIME للصورة في فهرس Siraj وتوقيع PNG/JPEG وحد البايتات البالغ 2 MiB. تكتب البلاطة المتحقق منها إلى ملف مؤقت في المجلد نفسه، مع `fsync` ثم استبدال ذري في الذاكرة المشتركة.
- لا تستبدل مهل المنبع أو الاستجابات غير الصالحة البلاطة المخبأة. وتمنع قاطعة دائرة قصيرة مشتركة محاولات المنبع المتكررة أثناء الانقطاع. إذا لم توجد بلاطة مخبأة، تعيد API خطأ 404 واضحاً (الجلب معطل/البلاطة غير موجودة) أو 503 (المزود غير متاح)، لا صورة زائفة.
- لا يدعم هذا الخادم تخزين البلاطات عند انقطاع اتصال المتصفح عن Bench. يستطيع مستخدم Desk المتصل الوصول إلى البلاطات إذا فقد خادم Bench اتصاله الخارجي بالإنترنت؛ أما المتصفح الذي لا يستطيع الوصول إلى Bench فلا يمكنه جلب ذاكرته الخادمية. لا يثبت التطبيق Service Worker ولا يخزن البلاطات في المتصفح.

## النشر على الموقع

بعد جلب تحديث التطبيق، نفذ:

```bash
cd ~/frappe-bench
bench --site frappe.com migrate
bench build --app camera_archive_management
bench --site frappe.com clear-cache
bench restart
```

في **CAM Geo Settings** راجع أولاً شروط المزود المحدد في **Geo Settings** (Siraj Research)، ثم فعّل **Enable Online Tile Fetch** و**Allow Shared Tile Cache Writes**. تحقق من تفعيل الطبقات المطلوبة في إعدادات Siraj الجغرافية ومن تفعيل إعداد **Allow server to fetch from provider** لديه. ستعرض خريطة Camera الطبقات النقطية المفعلة في Siraj فقط. عطّل أي إعداد CAM أو إعداد Siraj لإيقاف الطلبات الخارجية الجديدة والكتابة؛ وتظل البلاطات المتحقق منها سابقاً متاحة لقراء Camera المخولين.

يمكن تطبيق منع طارئ على مستوى الموقع بالأمر:

```bash
bench --site frappe.com set-config camera_archive_allow_online_tile_fetch false
```

## التحقق

من جلسة Desk مسجلة الدخول، استخدم وحدة تحكم DevTools للتحقق من الإعداد:

```js
fetch("/api/method/camera_archive_management.api.tiles.config")
  .then(async r => console.log(r.status, await r.json()));
```

ينبغي أن يعيد طلب بلاطة قياسية مخبأة أو جرى جلبها حديثاً HTTP 200 ونوع محتوى صورة، مع `X-CAM-Tile-Cache` بقيمة `HIT` أو `STALE` أو `MISS`:

```js
fetch("/api/method/camera_archive_management.api.tiles.tile?layer=standard&variant=base&z=9&x=305&y=208")
  .then(async r => console.log(r.status, r.headers.get("content-type"),
    r.headers.get("x-cam-tile-cache"), r.status >= 400 ? await r.text() : "image bytes"));
```

يختبر هذا الطلب أيضاً الإحداثيات التي تجاوزت سابقاً مدقق الأرقام ذي الرقم أو الرقمين وتسببت باستجابات 417. يجب أن يعيد الإحداثي خارج النطاق مثل `z=9&x=512&y=0` استجابة JSON بحالة HTTP 400. للاختبار دون اتصال، اجلب البلاطة وخزنها أولاً، ثم عطّل الجلب عبر CAM (أو امنع وصول مضيف Bench إلى المزود)، واطلب البلاطة نفسها؛ ينبغي أن تظل استجابتها HTTP 200 من الذاكرة. أما بلاطة أخرى غير مخبأة أثناء انقطاع المنبع فينبغي أن تعيد 503 ضمن المهلة المحددة، مع تحذير محدود التكرار في سجل الخادم.

اختبر تفويتات الذاكرة المتزامنة على بيئة مرحلية قبل الإنتاج؛ ينبغي أن ينتج عن قفل البلاطة طلب واحد للمزود لكل بلاطة مفقودة. للتحقق من رؤية Siraj للبلاطة نفسها، اطلب الطبقة المناظرة عبر `/api/method/siraj_research.tile_cache.tile` بمستخدم لديه صلاحية قراءة Place في Siraj، ثم تحقق من وجود الملف المطابق تحت `sites/frappe.com/private/siraj_tile_cache/`. لا تمسح الذاكرة المشتركة للاختبار؛ فالملفات في الشجرة نفسها تابعة إلى Siraj.
